# Vnstock Community setup

FinSight uses Vnstock Community locally and for its planned public Render deployment. The project owner attests that they asked the provider and were told public use is allowed. This records the owner's report only: it does not assert a written grant, invent scope or terms, or imply that Vnstock's software license itself grants rights to upstream VCI/KBS data. Keep use within the scope the owner confirmed and revisit it if distribution or use changes. Community requires an API key; Guest access cannot call the adapter's symbol-directory route.

## One-time setup

1. Create a free Community account and get an API key at <https://vnstocks.com/account#api-key>. Do not put the key in Git or chat.
2. Copy the root `.env.example` to `.env`, then set `VNSTOCK_API_KEY=<your key>`, `MARKET_PROVIDER=vnstock`, and `INSTALL_VNSTOCK=true`. The `.env` file is ignored by Git.
3. Start Docker Desktop, then run `docker compose up --build -d` from the repo root. Check `docker compose ps` and `docker compose logs worker --tail 40`.
4. Open `http://localhost:8000/api/v1/market/data-status` and `http://localhost:3000`. The source must be `vnstock`, not `csv-demo`.

For a Python-only setup, install both `requirements.txt` and `requirements-vnstock.txt` into `backend/.venv` and set the same environment variables. The optional package is pinned at 5.2.1. It is not installed in the public image by default.

The Compose API and worker share the `vnstock_auth` volume so the device identity persists across container rebuilds. Community permits one device. If Docker's data store is reset, the volume and identity are lost; remove the old device in the Vnstock account before registering a replacement. `VNSTOCK_SYMBOLS=ALL` imports the active HOSE, HNX and UPCOM equity directory; delisted entries are excluded. A comma-separated list can limit development. The worker fills two years of daily history in restartable batches of 50 symbols, starting the next batch within one minute. Each batch records an attempt checkpoint and reserves 20% of the account's reported minute, hour, day and month limits. `VNSTOCK_REQUEST_DELAY_SECONDS` defaults to 6 between provider calls, so the first full backfill takes hours. Watch `symbolCoverage` at `/api/v1/market/data-status`: `listed` is directory size, `withHistory` counts symbols with any price, and `currentToIndexDate` counts symbols with a bar on/after the latest VN-Index date. Tier-truncated history is rejected rather than stored as complete. VCI equity OHLCV is adjusted for corporate actions and quoted in thousands of VND; FinSight stores it in VND. Index OHLCV stays in index points.

The API key stays in the ignored root `.env`; ordinary restarts and image builds do not require a new key. Rebuild the worker when backend jobs change: run `docker compose up --build -d` for all services, or `docker compose up --build -d --no-deps worker` if only the worker image is stale. Rebuilding only backend/frontend leaves the previous worker image running. Preserve `vnstock_auth` and avoid `docker compose down -v` unless intentionally resetting local data and the Vnstock device identity.

## Public deployment on Render

The owner attests that they asked the provider and were told public use is allowed. This is not a claim that a written agreement was obtained; the project does not record unprovided scope or terms. Vnstock's software license does not by itself grant rights to upstream market data. Keep deployment within the owner's confirmed permission and stop public display if that permission no longer applies.

Render must run exactly one Vnstock-enabled background worker instance. Put `VNSTOCK_API_KEY` only in that worker's secret environment. Attach a paid persistent disk to the worker at the directory configured as `VNSTOCK_HOME` (the Compose image uses `/data/vnstock`); the disk preserves the one Community device identity across restarts and deploys. Do not scale this worker horizontally or run a second worker against the same one-device account. Render disks are accessible by only the attached service instance and cannot be mounted by the web service; they also disable zero-downtime deploys. See [Render persistent disks](https://render.com/docs/disks).

Set `MARKET_PROVIDER=vnstock` on both the web and worker so API reads select Vnstock rows. Only the worker needs the key, Vnstock package/device store, and provider credentials. The web service should serve persisted PostgreSQL bars and snapshots and must not make upstream Vnstock calls. PostgreSQL is the handoff between worker and web; do not attempt to share the device directory across services. Render's filesystem outside the mounted disk is ephemeral.

Deploy checks:

1. Confirm the Render worker image installs `requirements-vnstock.txt`, `VNSTOCK_HOME` matches the disk mount, and its disk is attached before enabling the provider. Keep one worker instance and verify the key is absent from web/frontend settings and build variables.
2. Confirm `MARKET_PROVIDER=vnstock` on web and worker; `RUN_SNAPSHOT_JOBS=false` on web; PostgreSQL and Redis connections are configured. Run migrations once through the deployment's controlled migration path.
3. In worker logs, confirm successful directory/history/quote sync without printing credentials or raw account data. A restart/redeploy must retain the same device identity and must not register another device.
4. Check `/health` and `/ready`, then `/api/v1/market/data-status` for `source=vnstock`, latest dates and job status; `/api/v1/market/board` for a persisted snapshot and its `snapshotAt`; `/api/v1/stocks?limit=10` for `source=vnstock`. The web service must answer these using PostgreSQL even though it has no provider key or disk.
5. Verify a provider failure leaves data marked stale/error/no-data and never yields `source=csv-demo`. Monitor `provider_job_runs`, worker restarts, and data freshness after deployment.

The universe worker fetches index history on a fresh database only; the EOD job advances it later. It does not mark a batch complete when the provider raises partway through. Successfully saved bars are idempotent on retry.

The market board is independent of that historical backfill. During trading hours the worker calls `Market().quote(symbols)` every five minutes for the whole active directory; outside trading hours it captures once per day and once after close. Each successful refresh atomically replaces the saved `market_snapshots` row for Vnstock. `/api/v1/market/board` reads that row; browser requests never call Vnstock. The quote feed uses KBS and returns VND prices. It returned all 1,516 directory rows in the 08/11/2026 check: 930 had a positive matched price, and all 1,516 had a positive reference price. The board shows reference price in its own column and leaves an absent matched price null. `snapshotAt` is the time FinSight fetched the board, not a per-symbol exchange trade timestamp. The UI labels it as a possibly delayed snapshot. Historical bars from VCI remain separate for charts and T+1/T+5; they are never synthesized from KBS quotes. A failed quote refresh keeps the prior snapshot and its older timestamp. See `docs/market-data-architecture.md`.

Data methods: `Reference().equity.list_by_exchange()` for the ticker directory; `Market().equity(symbol).ohlcv(source="vci")` for adjusted daily stock history; `Market().index(symbol).ohlcv()` for index history. This is end-of-day history, not a real-time exchange feed. If the provider fails, FinSight must show an error or stale state, never silently use synthetic prices.
